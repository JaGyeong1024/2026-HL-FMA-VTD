# HL FMA 대회 프로젝트 — 세션 규칙

## 세션 시작 시 (순서대로, 반드시)

1. **`대회정보.md` 읽기** — 대회 스펙·통신·인프라·결정사항의 통합 맥락 (항상 최신 유지. 문서 구조는 §12)
2. **최신 `todo*.md` 읽기** — 세션 핸드오프: "지난 세션에서 한 것 / 이번 세션에서 할 것 / 기술부채" (현재 최신: `todo0903.md`)
3. 관련 심화 문서 (필요 시): `런타임_노드그래프.md`(실측 노드·토픽 연결, 최종궤적=/planning/trajectory) · `주행리뷰_및_노드감사_0903.md`(근본원인·능력·노드감사) · `autoware_통합_검토_0901.md`
4. Redmine 미답변 질의가 있으면 답 달렸는지 사용자에게 확인 요청 (목록은 최신 todo 상단. 9/2 기준 미답변 없음)

## 문서 구조

- 인덱스: `문서_인덱스.md` — 모든 문서·자료 위치 지도 (여기부터 보면 됨)
- 활성(루트, .md): CLAUDE.md · 대회정보.md · 최신 todo(핸드오프) · 런타임_노드그래프 · 주행리뷰_및_노드감사 · autoware_통합_검토 · 개발계획
- `1차자료/`: 원본 참고자료 모음 (안내문 PDF 2종·인터페이스 API.xlsx·`게시판 QnA/`·VTD 메뉴얼·실습파일·교육·대회설명회 슬라이드·`센서인터페이스_역분석/`(07·08)·autoware_universe.png·route_example.csv). **원본, 수정하지 않음**
- `문서보관/`: 통합 완료된 이력 문서 (이전 todo, 세션 로그, 원본 정리본) — 새 문서가 대체하면 여기로 이동
- 문서는 늘리지 말 것: 새 내용은 대회정보.md(사실·스펙) 또는 최신 todo(진행·부채)에 통합이 기본
- 활성 .md 갱신 시 제어기 `~/2026-HL-FMA-VTD/docs/대회정보/`에도 동기화·커밋 (§세션 종료)

## 세션 종료 시

- 새 `todoMMDD.md` 작성 또는 기존 갱신: **이번 세션에서 한 것 + 다음 세션에서 할 것** 구조로
- 갱신한 문서는 제어기 PC `~/2026-HL-FMA-VTD/docs/대회정보/`에 동기화 + git 커밋 (사용자 명의, 커밋 메시지에 Claude 흔적 남기지 않기)

## 장비 접속 (비번 둘 다 `a`)

- 제어기 PC: `ssh a@100.120.213.124` (Tailscale) 또는 `ssh a@192.168.1.55` (같은 공유기)
- 시뮬 PC: `ssh a@192.168.50.11` (제어기 경유 서브넷 라우트)

## 작업 원칙 (사용자 지시 누적)

- 채점 세계 = 대회장 VTD가 읽는 xodr 원본. xodr 결함은 수정 아닌 회피·검증 대상
- 대회장 도구는 원커맨드 자동화보다 **사람이 이해·수정 가능한 구조** (설정 파일 + 독립 실행 단계, 로직 숨기지 않기)
- 편의적 선택(대충 넘어간 것)은 반드시 최신 todo의 기술부채 섹션에 원복법과 함께 기록
- 검증 안 된 구성 변경 최소화 — 실주행 관찰 → 간극 확인 → 그때 수정 순서
- 결정론적 실패에 재시도 자동화 금지
