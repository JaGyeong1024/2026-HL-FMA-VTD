## 2. 네트워크 구성 (연구실)

```
[외부/노트북] ──Tailscale──> [제어기 PC] ──Ethernet 직결──> [시뮬 PC]
                             192.168.10.1                  192.168.10.2
                             (Wi-Fi: 192.168.1.55)
```

| 장비 | 접속 | 비고 |
|---|---|---|
| 제어기 PC | `ssh a@192.168.1.55` (같은 공유기) 또는 `ssh a@hlfma-controller-pc` / `100.120.213.124` (Tailscale) | 계정 a / 비번 a, Ubuntu 24.04 |
| 시뮬 PC | `ssh a@192.168.10.2` (Tailscale 서브넷 라우트 경유, 어디서든) | 계정 a / 비번 a, Ubuntu 24.04, RTX 4090, 24코어, 64GB |

- 제어기 PC가 **Tailscale 서브넷 라우터** (`--advertise-routes=192.168.10.0/24`, 콘솔에서 승인됨) → 외부 장비는 `tailscale set --accept-routes` 켜면 시뮬 PC에 바로 접속 가능
- 제어기 PC Ethernet은 NetworkManager **공유 모드** (NAT+DHCP) → 시뮬 PC 인터넷 가능
- 시뮬 PC는 netplan 고정 IP (`/etc/netplan/50-cloud-init.yaml`: 192.168.10.2/24, gw 192.168.10.1, DNS 8.8.8.8)
- 방화벽 주의: NM 공유모드가 Tailscale→시뮬PC 포워딩을 막는 문제 → `/etc/NetworkManager/dispatcher.d/90-tailscale-to-sim` 스크립트가 링크 up/down마다 허용 규칙을 FORWARD 맨 위에 재삽입 (재부팅/링크단절에도 유지)
- GUI 원격: RustDesk 직접 IP 접속(시뮬 PC에서 허용 설정 필요) 또는 SSH 터널+RDP/VNC
- ⚠️ 대회장에서는: 공유모드 DHCP가 대회 네트워크를 교란할 수 있음 → 대회장용 프로필로 전환 필요 (대회 IP 스펙 확보 후 작성 예정). Ethernet 직결 트래픽은 NAT/Tailscale을 안 거치므로 자율주행 성능 영향 없음

## 3. 통신 인터페이스 (상세: 통신_인터페이스_정리.md)

| 채널 | 포트 | 내용 |
|---|---|---|
| TCP 9910 | 양방향 | 수신: **1109B 고정 패킷** `'<6f' + 'I8f'*30 + 'iB'` (ego 6f, objects 30슬롯, 신호등 1개) @20Hz / 송신: **9B** `'<ffB'` (steering rad, targetAccel m/s², turnSignal) |
| UDP 9912 | VTD→제어기 | LiDAR: 42B 헤더(`'<IHIQdHHIIHBB'`, magic 'IVHL') + float32 xyz, **월드좌표**, 34,752pts/frame, 실측 ~7fps (설정 20fps — 미달 원인 미조사) |
| RTSP 8554 | 제어기 pull | `rtsp://<시뮬PC>:8554/front` H.264 1080p 20fps, **`-rtsp_transport tcp` 필수** |

- objects: id=0 무효, 80m 이내 가까운 순 최대 30개. 신호등 state: 0미할당/1적/2황/3녹/4좌회전/5녹+좌/6점멸
- 예제 코드가 `steer_out = -steer` 부호 반전 사용 — 조향 부호 규약 확인 필요
- NaN 제어 패킷은 무시됨. 연결 끊기면 steering=0/accel=0 처리
- 시뮬 PC의 `~/HLFMA/docs/`에 팀이 만든 역분석 문서 있음 (07-sensor-interface.md, 08-ros2-sensor-bridge.md)

## 5. 오늘 해결한 문제들

| 문제 | 원인 | 해결 |
|---|---|---|
| LiDAR 데이터 안 나옴 (igLidarWriter FATAL, OptiX 0x60A) | `nvidia-driver-595-open`(오픈 커널 모듈)이 OptiX 6.5 미지원 | **독점 모듈 580.173으로 교체** (550 메타패키지가 580으로 전환 설치됨). OptiX 테스트 통과, LiDAR 수신 확인 |
| LiDAR가 제어기 PC에 안 옴 | `lidarDestinationIp: 127.0.0.1` | `192.168.10.1`로 수정 |
| 시뮬 점점 느려지다 멈춤 (시뮬1초=현실6초) | **8/17에 팀에서 수정한 시나리오**(v1~v7 전부 원본과 다름)가 ghostdriver 세그폴트 유발 → TaskControl이 매 프레임 Traffic 대기 | 주최측 원본(`ORIG_v5.xml`) 사용 시 3분+ 안정, 20.2Hz. 수정본의 웨이포인트/PathRef 편집이 유력 원인 |
| 시뮬 PC 재부팅 후 원격 접속 끊김 | NM이 방화벽 체인을 맨 위에 재삽입해 허용 규칙이 밀림 | dispatcher 스크립트가 항상 최상단 재삽입하도록 보강 |
| 시나리오 로드 실수 | 파일 선택창에서 `v5.xml~`(백업)이 로드됨 | `~` 파일들을 `Scenarios/.backup_tilde/`로 이동 |
