## 3. 오늘 알게 된 사실 / 판단

- **launch 파스는 lazy가 아님**: 조건이 참인 group 안의 find-pkg-share는 파스 시점에 즉시 해석 → 패키지 없으면 launch 전체 예외. ignore 처리는 "런타임에 그 경로를 타는가"가 아니라 "launch 인자·preset 기본값 기준 활성 경로인가"로 판단해야 함 (§2-4의 전수 감사가 그 작업)
- **adaptor류는 서비스 응답을 로깅 안 함**: goal 주입이 조용히 실패할 수 있음 → 디버깅은 ADAPI 서비스 직접 호출로 (응답에 사유 담김: "The planned route is empty" / "Goal is not valid")
- **goal pose의 heading은 그 지점의 차선 진행 방향**이어야 함 (다음 웨이포인트 방향 아님). 경로 주입 스크립트 구현 시 주의 — CSV 짝점(교차로 진입·진출)에서 heading은 진입 직전 주행 방향으로
- **mission planner는 goal 각도 검증함** (차선 방향과 불일치 시 거부). E2E에서 실증: 0.509rad(체인 방향) 거부 → 1.704rad(차선 방향) 성공
- `ros2 topic echo`는 대형 그래프에서 디스커버리 플레이크 있음 (127노드에서 15s 타임아웃 미스) → 판정은 AutowareState·operation_mode·실제 속도 같은 상태값으로
- route/state류 토픽은 transient_local → echo 시 `--qos-durability transient_local --qos-reliability reliable` 필요
