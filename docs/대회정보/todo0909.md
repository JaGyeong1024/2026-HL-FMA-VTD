## 4. "no safe path" 의 정체 (사용자 지적이 맞았다)

거절된 후보 실측 (t=50.04~50.08) — 동역학적으로 전혀 무리 없다:
```
lc_time 2.74~2.96 s | lat_acc 2.0~3.33 | lc_len 29~40 m | lon_acc 0.0
```

RSS 식 (`safety_check.cpp:307` 원본):
```
d_rss = v_rear × (반응시간 + 여유시간) + v_rear²/(2|a_rear|) − v_front²/(2|a_front|)
```
우리 값 대입 (자차 14.05 m/s, 앞차 정지, `prepare` 블록):
```
반응 0.3 + 여유 0.2 = 0.5 s,  expected_rear_deceleration = −1.0
d_rss = 14.05×0.5 + 14.05²/(2×1.0) = 7.0 + 98.7 = 105.7 m
앞 정지차 약 77 m  →  77 < 105.7 → unsafe
```
`−3.5` 로 바꾸면 `7.0 + 28.2 = 35.2 m` → **safe**.

**RSS 는 "자차가 1.0 m/s² 로밖에 못 선다"고 가정한다.** 50 km/h 정지에 99 m 가 필요하다는 뜻이고,
앞차가 100 m 안에 있는 한 어떤 차선변경도 영원히 unsafe 다.

`todo0908 §부록 B-2` 의 *"RSS 완화 후에도 95 m 앞 정지차에서 동일하게 거부"* 가 이것으로 설명된다 —
9/8 에 완화한 것은 **반응시간·마진(선형항 ≈7 m)** 이고, 지배항 **v²/2a (≈99 m)** 는 건드리지 않았다.

`allow_loose_check_for_cancel: true` 라 `manager.cpp:314` 의 FATAL 검증은 건너뛴다 — 안전하게 바꿀 수 있다.

## 5. obstacle_stop 이 "너무 앞에서" 나오는 이유

정지점 배치 자체는 정상이다 (`stop_margin: 5.0`, 정지차는 `enter_fixed_stop 3.0` 으로 현재 위치 기준).

문제는 **감속 시작 시점**이다:
```
t=50.17  정지점 68.3 m,  v=14.1 m/s     ← 여기서 이미 감속 시작
t=55.28  정지점 27.6 m,  v= 8.9 m/s
평균 감속 = (14.1² − 8.9²)/(2×40.7 m) = 1.47 m/s²
```

   (A* 가 같은 계획을 다시 내도 `last_key=None` 덕에 재적용되고, 새 스냅샷으로 재발동 안 함)
