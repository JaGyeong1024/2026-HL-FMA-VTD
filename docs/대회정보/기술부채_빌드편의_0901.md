## A. 반드시 정식화할 것 (대회 전)

1. **path_optimizer → path_sampler 프리셋 전환** (acados 미설치 회피)
   - 위험: Autoware 기본·최다 검증 모션 플래너에서 이탈
   - 정식화: acados 로컬 빌드(sudo 불필요) → `autoware_path_optimizer/COLCON_IGNORE` 삭제 → 빌드 → `default_preset.yaml` motion_path_planner_type을 path_optimizer로 원복
2. **~/autoware 소스 직접 수정이 버전관리 밖** — vehicle_info 2곳(아이오닉6), common.param.yaml(max_vel 13.3), default_preset.yaml
   - 조치(오늘 밤): 수정분을 patch로 추출해 repo `patches/`에 저장 ✅
   - 정식화: Autoware 업데이트/재클론 시 `git apply patches/*.patch`로 재적용. 장기적으로는 hlfma_vehicle_description 패키지 분리
3. **COLCON_IGNORE 일괄 88개** (perception/sensing/localization/evaluator 85 + tensorrt_common·diffusion_planner·path_optimizer)
   - 근거는 있음(플래닝 폐쇄가 해당 디렉토리 의존 0) 그러나 개별 검증 없이 일괄 처리
   - 목록: `patches/colcon_ignore_list.txt` ✅ / 원복: `find ~/autoware/src -name COLCON_IGNORE -delete`
4. **launch_system:=false** — engage(자율 전환)가 시스템 진단 없이 되는지 미검증. 안 되면 true로 켜고 diag 구성 조정
5. **tier4_perception/sensing/localization_launch 미빌드** — 우리 launch 인자로는 include 안 되지만, psim 모드가 참조하면 에러 가능. 발생 시 해당 launch 패키지만 증분 빌드

## B. 검증만 하면 되는 것

6. **is_simulation:=true** — 신호등 무데이터=통과 근거는 확인했으나(검토 문서 §5B), 이 플래그를 읽는 **다른** 노드 전수조사는 안 함. 내일 실주행에서 이상 거동 시 의심 목록 1순위
7. **더미 pointcloud_map.pcd (점 1개)** — pointcloud_map_loader 달래기용. 로더가 경고 이상을 내면 이 지점
8. **stderr 있었지만 통과한 패키지들** (eagleye, path_smoother 등) — 경고 수준으로 판단하고 방치. 링크·런타임 문제 시 재확인
9. **실패 패키지의 install 잔재 오염 가능성** — tensorrt_common처럼 실패했는데 install 디렉토리가 남아 "빌드됨"으로 오인된 사례 1건 있었음. 내일 빌드 성공 후 `colcon list --packages-select $(ls ~/autoware/install)` 대조 권장

## D. 환경 스킵
