# 주행 리뷰 · 노드 감사 (2026-09-03)

첫 end-to-end 자율주행 성공(~7 m/s 주행 후 goal 정지) 직후 작성. 짝문서: `런타임_노드그래프.md`.

---

## A. "차가 안 움직이던" 근본 원인 회고 (어제~오늘)

Autoware 자율주행으로 차가 움직인 적이 **한 번도 없었다.** (예전 "잘 감"은 VTD 시나리오 route가 ego를 끈 것 — 자율주행 아님.) 독립적 블로커 4개가 **각각** 파이프라인을 제어 도달 전에 끊었다:

| # | 블로커 | 증상 | 근본 원인 | 수정 |
|---|---|---|---|---|
| 1 | **route 미SET** | set_route 30s 타임아웃 | getMainLanelets 무한루프 — 네이티브 맵 좌/우 평행차선 위상 순환에서 바깥 while이 무한 append (ADAPI 서비스 점유) | route_handler 가드(patch) |
| 2 | **out of route** | route는 SET인데 behavior 모듈 안 돎 | route_node DP가 시작을 ego 실제 차선(56906) 아닌 옆차선(57203)으로 갈아탐(76m 절감) → route가 ego를 안 지남 | route_node 시작앵커=ego lanelet |
| 3 | **궤적 미생성** | behavior/path 10Hz인데 motion→trajectory 없음 | path_optimizer MPC(acados)가 **런타임에 acados 라이브러리 못 찾음** (/opt/acados로 옮겼는데 스크립트는 $HOME/acados) | ldconfig 시스템 등록 |
| 4 | **AEB IMU 대기 → 제어 미완결** | control_cmd 정지값(-1.5), mode STOP 고착 | VTD가 IMU 미제공 → 브리지가 `/sensing/imu/imu_data` 미발행 → AEB 초기화 못함 → 제어체인 미완결 → gate 정지·mode STOP | 브리지 IMU 합성 발행 |

4개 모두 해소 후: engage→AUTONOMOUS 유지 → controller가 `/planning/trajectory` 추종 → gate → CtrlPacket → **VTD ego 주행**.

핵심: **단일 결함이 아니라 4겹.** 하나 고치면 다음 겹이 드러나는 구조라 오래 걸림. + acados/ldconfig처럼 "이전 세션의 편의적 이동(→/opt)이 스크립트와 어긋난" 부채가 섞여 있었음.

## B. 과정 중 오해였던 것 (재발 방지 기록)

1. **최종 궤적 토픽 오인** ★가장 큰 오해★ — `/planning/scenario_planning/trajectory`(우리 구성 **미사용**, 발행자 0)를 "최종"으로 보고 오래 헤맴. 진짜 최종은 planning_validator가 내는 **`/planning/trajectory`**(10Hz 정상). → 실제 노드 그래프(`ros2 node info`)를 늦게 확인한 탓.
2. **"5.8s trajectory delayed"를 지속 결함으로 오인** — scenario_selector가 첫(startup) 낡은 궤적 1회 거부한 것. 이후 신선(0.1s)해 정상 전달. 스냅샷 타이밍이 겹쳐 지속으로 착각.
3. **localization/state STALE를 블로커로 오인** — startup 과도기. 브리지가 initialization_state=3 발행, /adapi/node/localization 수신 정상. 블로커 아님.
4. **"acados가 유일한 돌파구"라 성급 → 다시 성급 철회** — ldconfig는 진짜 수정(궤적 10Hz)이나 **단독 불충분**(IMU도 필요)이었음. 과잉 주장·과잉 철회 둘 다 잘못.
5. **parking 패키지 없음으로 가정** — 실제로 freespace_planner 실행 중(대기). 블로커와 무관.
6. **gear_cmd "not received"를 브리지 갭으로 오인** — Autoware 내부 shift_decider 소관, 궤적 흐르면 해소되는 startup 증상.
7. **배포 맵이 큐레이션 v2로 착각** — 실제 네이티브 33MB. (단 validator 에러 0이라 블로커는 아님.)

교훈: **증상(diag)보다 실제 노드 I/O 그래프를 먼저 떠야 한다.** 토픽 이름 추정 금지.

## C. 능력 현황 (검증됨 / 배선-미검증 / 구조적 한계)

| 능력 | 상태 | 근거·비고 |
|---|---|---|
| 직진 주행 → goal 정지 | **✅ 검증** | 오늘 실주행(clean_test 185m 직진) |
| **폐루프(같은 lanelet 재통과) 단일경로** | **❌ 구조 불가** | Autoware route=단순경로, lanelet 재방문 금지("no loop allowed"). 진짜 필요시 route 분할 주입. **대회는 점대점이라 무관** |
| 시작점/ego 위치 무관 | **△ 조건부** | route_node가 ego **실제 lanelet에 시작 앵커** → ego가 매핑된 차선 위 + 정방향이면 OK. off-lane·역방향·차선 애매지점은 미검증/위험 |
| 중앙선 준수(우측통행) | **✅ 구조적** | 경로=방향성 lanelet 열, 중심선 추종 → 반대편 안 밟음 |
| 좌회전=안쪽차선/우회전=바깥차선 선택 | **△ 배선-미검증** | CSV 교차로 진입·진출 짝점 + 맵 회전lanelet(turn_direction) + behavior에서 **창발**. 하드룰 없음. **실주행 검증 필요** |
| 차선변경 적절 거리 | **△ 배선-미검증** | behavior_path_planner lane_change 모듈. 실주행 검증 필요 |
| 주변 객체 인지·회피/정지 | **△ 배선-미검증** | 브리지 GT objects→behavior avoidance/obstacle_stop/cruise. **GT objects만**(실 LiDAR 없음) → objects[30] 밖·정적장애물은 미인지 위험 |
| 신호등 인지·정지 | **△ 배선-미검증** | 브리지 신호등 state→다음 정지선 규제요소. 실주행 검증 필요 |
| 보호구역(스쿨존) 감속 | **△ 배선-미검증** | 맵 speed_limit(붉은노면 lanelet). 붉은노면 식별 정확도 검증 필요 |

**정직한 바닥선: 검증된 것은 "직진 주행+정지" 하나.** 나머지는 배선은 되어 있으나 **실주행 미검증** — 지금부터가 "실주행 관찰→간극→수정" 단계.

## D. 노드별 대회환경 적합성 감사 (VTD 제공정보 = GT pose·objects·신호등 state뿐; IMU·속도·정지선좌표·스쿨존좌표 미제공)

각 노드가 **필요로 하는 입력 vs 실제로 받는 것(GT/합성/더미)** → 대회 채점에 미칠 리스크.

### D-1. Localization 대체 (브리지, GT pose)
- kinematic_state pose: GT → 정확. **twist(속도·각속도)=pose 차분+LPF 추정 → 노이즈 큼**(실측 7↔2.7 튐).
- **⚠ 리스크(高)**: ① 채점은 **VTD 실속도** 사용(QnA5) — 우리 추정속도와 불일치 → 제한속도(항목1)·보호구역(항목2) 판정과 우리 제어의 기준이 어긋날 수 있음. ② 속도 노이즈가 종방향 제어(가감속)·정지 정밀도에 영향. **→ 최우선 검증·개선 대상**(필터 강화 또는 더 나은 속도추정).

### D-2. Perception 대체 (브리지 GT objects + 더미)
- objects[30]: GT 위치·속도·크기·id → 정확. yaw rate·예측경로는 프레임차분 추정.
- 더미 pointcloud(빈)·occupancy(전부 free): **미지·정적 장애물 미인지.**
- **⚠ 리스크**: ① NPC 급정지·끼어들기(항목14) 회피는 GT objects+예측으로 가능하나 **예측 품질**이 관건. ② objects[30] 초과·정적 콘 등은 안 보임(항목11 경미). ③ 보행자(항목10)는 objects에 있으면 인지 가능.

### D-3. 신호등 (브리지 라우터 + behavior_velocity traffic_light)
- state는 GT. 브리지가 **경로상 다음 정지선의 규제요소**에 가라/서라 부여.
- **⚠ 리스크(高)**: **정지선 위치는 미제공**(QnA1) → 우리는 xodr signal/정지선 object에서 추출한 맵 기준. 채점은 **범퍼 기준 정지선 2m 이내**(항목7). **우리 정지선 좌표가 실제와 어긋나면 감점.** state6(점멸)은 브리지 상태기계로 처리. **→ 실주행 감점로그로 정지선 오차 확인 필수.**

### D-4. Planning
- **mission_planner/route_node**: CSV→경로. **⚠ sparse CSV 순환 취약**(오늘 확인) — 대회장 CSV(교차로 짝)로 완화되나 **loopless 매칭 미완**. 시작앵커=ego는 확보.
- **behavior_velocity (stop_line·crosswalk·traffic_light·speed_bump 등)**: 맵 규제요소 기반. **정지선·횡단보도·보호구역 좌표 미제공 → 맵 추출 정확도가 채점 좌우.**
- **behavior_path (lane_change·turn)**: 회전차선 선택·차선변경. **미검증.**
- **motion (path_optimizer acados·motion_velocity)**: 속도프로파일. **⚠ 순항속도가 제한속도(일반 50→마진 46, 보호 30→28)에 맞는지 검증**(오늘 관측 target_vel 0.25는 출발 순간값으로 추정, 순항속도 확인 필요).
- **planning_validator**: 곡률·횡가속·속도 임계. **⚠ 회전부 급곡률·좁은 회전lanelet에서 무효판정→궤적 끊김 위험**(오늘은 직진이라 통과).

### D-5. Control
- trajectory_follower: **노이즈 속도 입력** 의존 → 추종·정지 정밀도.
- vehicle_cmd_gate: jerk/accel 필터(startup jerk±0 전이 있었음), 모드 게이팅. 정상시 통과 확인.
- AEB: 합성 IMU로 동작. **⚠ GT objects 기반 오제동(false braking) 가능성** 검증.
- shift_decider: 속도부호로 기어 → 전진만이라 무난.

### D-6. System / ADAPI / 진단
- diag_graph: 브리지 소스충족으로 autonomous 가용. **⚠ 주행 중 어느 필수 diag가 흔들리면 MRM/STOP** — 대회장 20분·무개입이라 **기동~주행 안정성(진단 flicker 없음) 리허설 필수.**
- MRM(comfortable/emergency stop): 트리거 조건 검토 — 오작동 시 주행 중 정지 위험.

## E. 실주행 검증 계획 (이 감사와 짝, 노드그래프 따라)
1. **속도추정 정확도** (D-1): VTD 실속도(가능하면 mainRS 계기판/시나리오) vs 브리지 추정 대조 → 필터 개선.
2. **순항속도·제한속도 준수** (D-4 motion): 직선/스쿨존에서 목표속도 실측.
3. **회전·차선선택·차선변경** (D-4 behavior_path): 실제 Path7 교차로에서 관찰.
4. **신호등·정지선 정지 정밀도** (D-3): 감점로그로 정지선 오차.
5. **객체 회피/정지·보행자·NPC 돌발** (D-2): 시나리오 이벤트에서.
6. **진단/MRM 안정성·20분 리허설** (D-6).
7. route_node **loopless 매칭**(대회장 CSV 짝) 강건화.
