# 정체 차로 교착 — 조사 기록 (2026-09-05)

> 상황: 좌회전을 해야 하는데 **자차 차로와 좌회전 차선이 모두 영구 정지 차량으로 막힘**.
> 우측 차로는 비어 있으나 Autoware가 그리로 가지 않고 정지. 9회 시도 후에도 미해결.
> 목적: 같은 시도를 반복하지 않기 위한 기록. 위치·방향 하드코딩은 대회에서 못 쓰므로 제외.

## 1. 실측 상황

정지 지점 ego (291.5, −1.5), lanelet 15414 (4차선 도로의 2차선), 폭 3.2 m.

```
     좌1 (좌회전 차선)        자차 차로            우1·우2
  ───────────────────    ─────────────────    ─────────────
    33.1m  ■ 정지                                (객체 0개)
    23.9m  ■ 정지          23.5m  ■ 정지         (완전히 빔)
     8.3m  ■ 정지          10.8m  ■ 정지
    -1.1m  ■ 정지 ←옆        0.0m  ▲ 자차
```

경로 구간 seg3 = `primitives [15379, 15414, 15449, 15484]`, `preferred = 15379`(좌회전 차선).
**우측 차로는 이미 경로에 포함**되어 있어 그리로 가도 경로 이탈이 아니다.
전체 73개 구간 중 58개가 이런 다차선 구간이다.

## 2. 핵심 물리 제약 — 정지 후에는 못 빠져나온다

RTC로 우측 차선변경을 승인해도 `dist_start = -inf` (경로 미생성).
정지 상태에서 좁은 틈으로 비집는 기동은 Autoware의 생성 대상이 아니다.

**따라서 어떤 해법도 "멈추기 전"(접근 중 40~80 m, 12 m/s)에 작동해야 한다.**

## 3. 접근 중 관측 — 우측 회피는 실제로 성립했다가 무너진다

`/planning/cooperate_status/*` 를 접근 전 구간에 걸쳐 관측:

```
 t     v      앞 정지차   RTC 후보
10.1  13.03    79.4m    static_obstacle_avoidance_right (True, start 23.4, finish 81)  ← 성립
                        조향요인에 ('avoidance','RIGHT') 등장                          ← 시도5 적용 시
11.1  12.49    66.6m    static_obstacle_avoidance_right (True, start -inf)             ← 무너짐
...
정지                     후보 소멸, lane_change_left 만 남음
```

원인: 로그의 `"return shift line is not feasible. do nothing.."`.
`static_obstacle_avoidance`는 **비켜났다가 원래 차로로 돌아오는** 기동만 만든다.
차량이 한 대 보일 때(79 m)는 성립하지만, 가까워져 **줄지어 선 차량이 다 보이면
돌아올 자리가 없어** 무효가 된다.

"비켜서 그대로 머무는" 담당은 `avoidance_by_lane_change` 인데 **9회 중 한 번도 후보를 내지 않았다.**

발동 조건 (`avoidance_by_lane_change_module/src/scene.cpp:97-134`):
```cpp
if (data.target_objects.empty()) return false;
if (num_of_avoidance_targets < 1) return false;   // avoid_required 인 객체 수
return nearest.longitudinal > max(최소차선변경길이, 최소회피길이);
```
거리 조건(79 m)은 충족되므로 앞 두 관문에서 걸린다.

## 5. 확정된 사실

- 경로에는 이미 폭이 있다(`primitives`에 4개 차선). 문제는 폭이 아니라 **`preferred` 방향으로만 움직이는 `lane_change` 로직**
- **정지 후 탈출 불가** — `dist_start=-inf`
- `static_obstacle_avoidance` 는 **돌아오기가 성립해야** 회피한다. 차량 열에는 안 통함
- `avoidance_by_lane_change` 는 후보 자체를 안 만든다 (원인 미특정)
- 우측 관련 모듈 `lane_change_right`, `avoidance_by_lane_change_*` 는 전 구간 "후보 없음"

## 10. 파라미터 조사 결론 (11회 소진)

**① `static_obstacle_avoidance` 는 구조적으로 이 상황을 못 푼다**
"비켜났다 원래 차로로 돌아오기"만 생성한다. 정지 차량 1대가 보이는 79 m 지점에서는
`safe=True, start=23.4, finish=81` 로 성립하지만, 접근해서 **줄지어 선 차량이 모두
보이면 돌아올 자리가 없어** `start=-inf` 로 무너진다.
돌아오기 조건을 푸는 시도(7·8·9) 전부 실패, 7은 오히려 방향이 뒤집혔다.

**② `avoidance_by_lane_change` 는 어떤 조건에서도 후보를 만들지 않는다**
마진(6)·객체필터(2)·정책(1)·단독실행(10) 전부 후보 0건.
발동 조건 `scene.cpp:97-134` 의 앞 두 관문
(`data.target_objects.empty()` / `avoid_required` 개수)에서 걸리며,
파라미터로 도달 가능한 범위 밖으로 보인다.

**③ `lane_change_left` 도 접근 중 무너진다**
72 m 지점 `(True, 50.0, 133.6)` → 61 m `(True, 26.1, 109.7)` → 50 m 부터 `-inf`.
좌측 차선이 정체로 막혀 있으므로 당연한 결과.

**결론: 이 상황은 Autoware 파라미터 조정으로 해결되지 않는다.**

## 12. 다음 실험: 관측 기반 재라우팅 (하드코딩 아님)

핵심 근거: **`lane_change` 는 route 의 `preferred_primitive` 방향으로는 확실히 동작한다.**
따라서 preferred 를 비어 있는 병렬 차로로 바꾸면 그 방향으로 차선변경이 생성될 것으로 기대.

일반 규칙 (위치·방향 고정 없음):
```
접근 중(아직 정지 전) AND 자차 차로 전방 80m 내 정지차량 N대 이상
        ↓
현재 route segment 의 primitives 중, 관측상 정지차량이 없는 병렬 차로를 선택
        ↓
그 차로 중심선 위 점을 경유점으로 clear_route + set_route_points
```
- 방향은 관측으로 결정 (좌/우 고정 아님)
- 대상 차로는 route 의 `primitives` 안에서만 선택 → **경로 이탈 아님**
- **반드시 정지 전에 발동해야 함** (§2 제약)

시도 3 은 같은 아이디어였으나 **이미 정지한 뒤** 주입해서 실패했다.


## 16. 승인 타이밍 경합 — 해결 (2026-09-06)

### 원인
`autoware_rtc_interface/src/rtc_interface.cpp`

```cpp
void RTCInterface::updateCooperateCommandStatus(const std::vector<CooperateCommand> & commands) {
      itr->command_status = command.command;
      itr->auto_mode = false;        // ← 수동 명령이 오면 그 UUID 의 자동승인을 끈다
}

bool RTCInterface::isActivated(const UUID & uuid) const {
  if (itr->auto_mode && !itr->requested) return itr->safe;   // 자동승인 경로
  return itr->command_status.type == Command::ACTIVATE;      // 수동 경로
}
```

`requested` 는 lane_change 에서 항상 false 다
(`interface.hpp:111` 오버로드의 3번째 인자는 `safe`, `updateCooperateStatus` 의 `requested` 는 기본값 false).

따라서 **자동승인이 켜져 있으면 `isActivated` 는 `safe` 를 그대로 반환** — 명령이 필요 없다.
그런데 실험 스크립트가 ACTIVATE 를 보내면 `auto_mode=false` 로 강등되어
수동 경로로 떨어지고, 후보 경로 재계산으로 UUID 가 바뀌면 명령이 승계되지 않는다.
이것이 `(safe=True, cmd=0)` 인데도 승인되지 않던 이유다.

### 조치
`/tmp/detour2.py` 에서
- 수동 ACTIVATE 전송 2블록 **삭제**
- 경로 재전송 retry **삭제** (모듈 리셋 → UUID churn 유발)
- `/planning/auto_mode_status/<module>` 구독 + 전 사이클 RTC 전이 로깅 추가

저장소 설정은 이미 `scene_module_manager.param.yaml` 에서 lane_change 계열 전부
`enable_rtc: false` → `is_auto_mode_enabled_ = !enable_rtc = true` 이므로 **설정 변경 불필요**.
경합은 실험 코드에만 있었다.

### 검증 결과 (실주행)
```
[발동] 정지차 2대(최근접 37.4m, v=8.6), 자차 lanelet 15414 잔여32m, preferred=15379
   15379(좌) 정지차 1대 → 막힘 / 15449(우) 정지차 0대 → 선택
change_route: True     반영확인 seg0 preferred=15449
[RTC 7.9s] am=True [(bce76e11, safe=True, start=9.0, finish=66.9, state=1, cmd=0, auto_mode=True)]
```
`state=1(RUNNING)`, `cmd=0(DEACTIVATE)`, `auto_mode=True`
→ **수동 명령 없이 자동승인만으로 차선변경 모듈이 승인·실행 상태 진입.** 경합 해소 확인.

### 이 수정으로 드러난 다음 병목 (별건, 미해결)
자차는 shift 시작점(7.3 m 앞) 도달 전에 정지한다.

```

  module: obstacle_stop
  control_points[0].distance: -0.097     ← 정지점이 자차 바로 위
```

`obstacle_stop` 이 앞 정지차 때문에 자차 위치에 정지점을 삽입 →

차선변경 전체 소요 65 m 중 가용 구간은 약 15 m 로, 13절의 거리 부족과 동일한 문제.


## 17. external-request 우회 후보 미생성 추적 (2026-09-06)

- 후보 `/planning/path_candidate/external_request_lane_change_*`는
  `autoware_planning_msgs/Path`이다. 우회 노드의 `PathWithLaneId` 구독을 수정하고
  실제 DDS 송수신을 포함한 Python 테스트 11개를 통과했다.
- 재실행 관측: `fresh=True`인데 후보 0점. 접근 중 우측 RTC는
  `(safe=False, start=-inf, finish=-inf)`이며 정지 후 전방 객체 거리는 약 10.915m.
  초록 좌회전 신호에서도 정지 유지. 승인 요청 로그 없음.
- 동시 Autoware 로그: `lane_change.EXTERNAL_REQUEST: lanes are not available. Not expected.`
- 소스 원인: `get_target_neighbor_lanes`가 non-mandatory 모듈에서 우선 차로만 남긴다.
  `EXTERNAL_REQUEST`도 이 분기에 들어가 우선 차로에 도달하기 전 우회 시
  출발 차로를 제외할 수 있다. `is_lanes_available`는 이 목록이 비면 false다.
- 수정: 외부 요청에 한해 현재 차로 열을 유지한다. 라우팅 그래프의 인접 차로 선택,
  후보 경로 유효성 검사와 충돌 검사는 유지한다.
- 별도 빌드 성공, 신규 비우선 차로 회귀 테스트와 기존 관련 테스트 총 5개 통과.
- 패치: `patches/external_request_lane_change_non_preferred.patch`.
- 제한: 실제 시나리오에서 우회 및 좌회전 완료는 아직 확인하지 못했다.
