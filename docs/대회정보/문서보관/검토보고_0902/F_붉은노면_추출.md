## 2. 방법

### 2.1 osgb → osgt

`osgb`는 zlib 압축 OSG 바이너리(헤더 magic `a1 0e 91 6c 45 45 fb 1a`, `zlib`). 시스템 `osgconv`(OpenSceneGraph 3.6.5, `osgdb_osg.so`)가 그대로 읽는다. gunzip 선처리 불필요.

```
# 1차: 텍스처 이미지가 base64로 내장되어 976 MB
osgconv HL_FMA_VTD_LivingLab.osgb out.osgt
# 2차(채택): 이미지를 외부 파일로 빼서 99 MB + 텍스처 원본 42개 확보
cd tex && osgconv -O "WriteImageHint=WriteOut" ...osgb ../out.osgt
```

`WriteImageHint=WriteOut` 이 핵심. 이걸 안 쓰면 osgt의 90%가 이미지 base64라 파싱이 무의미하게 느려진다.

### 2.2 붉은 텍스처 식별

osgt에 나타난 텍스처 이름 108종 중 실제 이미지가 떨어진 42종의 평균 RGB와 "붉기"(`R − (G+B)/2`)를 계산했다. **노면(도로 표면) 계열에서 붉은 것은 `StyleSrfBikeway.rgb` 단 하나**:

```
StyleSrfBikeway.rgb        1024x1024  mean=(131.6, 59.6, 59.6)  redness= +72.0
TxKoSrfStreetUrban01.rgb   (일반 아스팔트)  mean=(116,116,116)   redness=  −0.0
StyleSrfStreetRestrict01.rgba (사선지대 표시) mean=(149,149,149)  redness=  +0.8
StyleCobble02 / StyleCurbstone02 / StylePatchy* / TxSrfStreetSidewalk01 … 전부 무채색
```

붉기가 큰 나머지(`TxSrfRoofTilesBeaverRed03`, `TxNxgnRoof01`, `TxBldShopSingle05`, `TxRoadMarkMasterSolidYellow`, `029/030/031_Ruby42_*` 등)는 지오메트리 bbox의 z 연직 범위가 10 m 이상 → 지붕·건물 외벽·노란 차선이며 노면이 아님을 확인해 배제했다.

### 2.3 지오메트리 추출

`parse_osgt.py`가 osgt를 한 줄씩 스트리밍하며 중괄호 깊이로 씬그래프를 추적한다.

- **MatrixTransform 누적**: 이 DB에는 `osg::MatrixTransform` / `PositionAttitudeTransform` 이 **0개**다(파서가 카운트해서 보고). 계층은 `Group → LOD → Geode → Geometry` 뿐이므로 `Vec3Array` 정점이 곧 DB 월드좌표다.
- StateSet은 공유될 수 있어 `UniqueID → 텍스처집합` 맵으로 참조(빈 본체 `osg::StateSet { UniqueID n }`)를 해소한다.
- `StyleSrfBikeway.rgb` 를 참조하는 Geometry **111개**, 정점 **64,914개**, 프리미티브는 전부 `DrawArrays TRIANGLES` → 삼각형 21,638개.
- LOD 때문에 같은 노면이 3~5개 LOD 레벨로 중복 저장되어 있다. 이후 폴리곤 유니온으로 중복이 자동 흡수된다.

### 2.4 구역화

삼각형 무게중심을 8 m 격자로 연결성분 분해 → 21개 클러스터. 각 클러스터의 삼각형을 shapely `unary_union` 후 `buffer(+0.15).buffer(−0.15)` 로 LOD 이음매를 메워 폴리곤을 만들었다. 2 m² 미만 파편은 버림.

추가로 폴리곤 간 거리 25 m 이내를 묶어 **회랑(corridor) C0~C13** 을 만들었다. 붉은 포장은 교차로에서 끊기므로, "한 구역"의 실제 물리적 단위는 회랑 쪽에 가깝다.

## 3. 좌표계 검증 (핵심 근거)

세 가지로 교차 검증했다.

1. **학교 건물 위치**: 텍스처 `TxBldResSchool_01.rgb` 를 쓰는 지오메트리가 정확히 1개, bbox x 512.1~554.4 / y −117.1~−50.3 / z 41.8~58.8, 중심 (527.4, −86.1). B 보고서의 "학교 건물 (528, −86)"과 일치.
2. **최대 후보 일치**: 정점 수가 가장 많은 붉은 지오메트리의 bbox가 **x 478.479~521.923 / y −141.603~−68.206**. B 보고서 휴리스틱 후보 (x 478~522 / y −142~−68)와 소수점까지 일치.
3. **평행이동 스캔(정량)**: 붉은 유니온 폴리곤을 dx,dy ∈ [−3, +3] m, 0.5 m 간격으로 옮기며 xodr driving 차로 폴리곤과의 면적 교집합 비율을 측정.

```
best overlap 0.9430  at  dx = 0.0,  dy = 0.0     ← 정확히 원점에서 최대
dx=±0.5 또는 dy=±0.5 만 줘도 0.943 → 0.91 이하로 하락
y 부호 반전(flip_y): 0.026     x/y 축 교환(swap_xy): 0.000
```

→ **osgb 정점 프레임 = xodr 월드 프레임, 항등 변환.** 오프셋도 축 뒤바뀜도 없다.
(남는 5.7%는 붉은 포장이 차로 폴리곤 바깥, 즉 노견·연석·교차로 코너를 조금 덮기 때문이다.)

z도 정합한다: 붉은 노면 z 40.0~72.3 m, 시나리오 Ego 초기 z=42.0 @ (508.8, −168.3), 해당 지점 붉은 노면 z=42.0.

## 4. 붉은 노면이 "차로 전폭"임을 확인

`lanecov.py`: xodr driving 차로마다 (inner, outer) 경계로 차로 **면적 폴리곤**을 만들고 붉은 유니온과의 면적 피복률을 계산.

```
붉은 면적 12,752 m² / 전체 driving 차로 면적 255,175 m²
접촉 차로 115개 →  피복률 >70%: 100개 ,  30~70%: 10개 ,  <30%: 5개
피복된 차로의 평균 폭 2.81 m
```

즉 좌·우 양방향 차로(lane id −1, +1, ±2 …)가 통째로 100% 붉게 칠해져 있다. 한국식 자전거도로(폭 1.5 m 띠)나 미끄럼방지 부분포장이 아니라 **차도 전폭 적색 포장**이다. 차로 폭 2.8~3.4 m 는 이면도로·생활도로 규격.

참고: xodr에는 `biking` 타입 차로가 아예 없고, `<speed>` 레코드도 0개다. 즉 **속도제한 정보는 xodr 어디에도 없으며, 시각모델의 붉은 포장이 유일한 단서**다.

## 8. 불확실성 / 남은 위험

1. **의미 라벨이 없다.** osgb는 "붉은 텍스처"만 알려줄 뿐 어린이보호구역/생활도로/보행자우선도로를 구분하지 않는다. xodr에는 `<speed>` 레코드도 `biking` 차로도 없어 교차검증할 원본이 없다. 학교 옆 회랑(C2/C4/C1)은 어린이보호구역이 거의 확실하지만, 남서쪽 C3·동쪽 C0/C5/C6/C7 까지 같은 30 km/h로 볼지는 **판단**이다.
   - 확인 수단: (a) VTD 뷰어로 해당 구역의 표지판(어린이보호구역 표지) 3D 오브젝트 확인, (b) xodr `<signal>` 중 해당 s 구간에 속도 표지가 있는지 스캔, (c) 대회 Redmine 질의.
2. **텍스처 이름이 `StyleSrfBikeway`** 다. 이름만 보면 자전거도로지만, §4에서 보듯 실제로는 양방향 차로 전폭을 덮고 있어 자전거도로로는 설명되지 않는다. RoD(도로 저작도구) 스타일 라이브러리에서 "붉은 아스팔트" 재질을 재활용한 것으로 본다.
3. **구역 경계는 시각 폴리곤 경계**다. 실제 규제 구간의 시종점(표지판 위치)과 몇 m 어긋날 수 있다.
4. **LOD 중복**을 폴리곤 유니온으로 흡수했지만, LOD 레벨 간 정점이 미세하게 다르면 0.15 m 버퍼로 메운 자리가 실제 형상과 최대 0.15 m 차이날 수 있다. 면적 수치의 유효자릿수는 3자리로 보면 된다.
5. **텍스처 42/108만 이미지 확인**. 나머지 66종은 osgconv가 파일로 쓰지 않았다(이름만 존재). 이들 중 노면 후보는 지오메트리 z 연직범위로 배제했으나, 완전한 색상 확인은 아니다. 다만 노면 계열 이름(`*Srf Street*`, `Style*`, `roadmark*`)은 전부 확인됐다.
6. **적용 금지 원칙 유지**: 이 결과로 맵을 수정하지 않았다. Lanelet2에 `speed_limit` 을 넣는다면 익스포터(`export_lanelet2.py`)에 lanelet id 목록을 주입하는 방식이 맞고, 그 전에 §8-1의 확인을 먼저 하는 것을 권한다.
