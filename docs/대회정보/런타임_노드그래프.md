## 0. 요약 — 표준 Autoware 대비 우리 구성

start_autonomous.sh 는 `autoware.launch.xml` 을 직접 기동하며 다음 서브시스템을 **끈다**:
`launch_perception:=false launch_localization:=false launch_sensing:=false launch_vehicle_interface:=false`
(system 은 켬, `system_run_mode:=planning_simulation`, `is_simulation:=true`, dummy_diag_publisher 켬)

| 표준 서브시스템 | 우리 상태 | 대체 |
|---|---|---|
| Sensing (camera/lidar/imu/gnss driver) | **끔** | 브리지가 IMU 합성, LiDAR/카메라 미사용 |
| Localization (ndt/ekf/pose_init) | **끔** | 브리지가 VTD **GT pose** → kinematic_state·tf·initialization_state |
| Perception (검출/추적/신호등) | **끔** | 브리지가 VTD **GT objects** → PredictedObjects, 신호등 라우팅, 더미 pointcloud/occupancy |
| Vehicle interface (raw_vehicle_cmd_converter/CAN) | **끔** | 브리지가 gate 출력 `/control/command/control_cmd` 직접 구독 → CtrlPacket |
| **Planning** (전체) | **켬** | — |
| **Control** (전체) | **켬** | — |
| System(진단/MRM) · Map · ADAPI | **켬** | — |

## 1. 데이터 경로 한눈에 (VTD ↔ Autoware)

```
                 TCP 9910 DataPacket(1109B, 20Hz)
   [VTD]  ───────────────────────────────────────►  [vtd_autoware_bridge]
   (ego GT pose·objects·신호등)                         │
                                                        │ ROS 토픽 (아래 §2 발행)
                                                        ▼
   [vtd_route_node] ─ /api/routing/set_route ─►  [Autoware Planning] ─► [Autoware Control]
   (CSV→lanelet 경로 주입)                                                    │
                                                        ┌───────────────────────┘
                                                        │ /control/command/control_cmd
                                                        ▼
   [VTD]  ◄───────────────────────────────────────  [vtd_autoware_bridge]
                 TCP 9910 CtrlPacket(9B, 20Hz: steer·accel·turn)
```

## 2. 브리지 = 경계 노드 (`vtd_autoware_bridge`)

**구독 (Autoware → VTD 로 내보낼 것):**
| 토픽 | 용도 |
|---|---|
| `/control/command/control_cmd` | gate 최종 제어 → CtrlPacket steer(rad)+accel(m/s²) |
| `/control/command/turn_indicators_cmd` | 방향지시등 → CtrlPacket turn 바이트 |
| `/planning/mission_planning/route` | 신호등 라우터(경로상 정지선) — 제어 아님 |

**발행 (VTD GT/합성 → Autoware 입력):**
| 토픽 | 원천 | 표준에서 원래 누가 | 비고 |
|---|---|---|---|
| `/localization/kinematic_state` | ego GT pose | (localization) ekf | twist=pose 차분추정 |
| `/localization/acceleration` | 추정 ax | (localization) | |
| `/localization/initialization_state` | 첫패킷 후 =3 INITIALIZED | pose_initializer | latched. **없으면 autonomous 불가** |
| `/sensing/imu/imu_data` | **합성**(wz·ax) | (sensing) imu_driver | **AEB 필수. 09-03 추가** |
| `/vehicle/status/velocity_status` | 추정 vx | (vehicle_if) | |
| `/vehicle/status/steering_status` | 명령값 1차지연 | (vehicle_if) | 실측 없음 |
| `/vehicle/status/gear_status` | =DRIVE 고정 | (vehicle_if) | VTD에 기어 없음 |
| `/vehicle/status/control_mode` | =AUTONOMOUS 고정 | (vehicle_if) | **OMTM 전환에 필요** |
| `/vehicle/status/turn_indicators_status`·`/hazard_lights_status` | 명령 에코/DISABLE | (vehicle_if) | |
| `/perception/object_recognition/objects` | VTD GT objects[30] | (perception) | PredictedObjects, yaw·예측 추정 |
| `/perception/traffic_light_recognition/traffic_signals` | VTD 신호등 | (perception) | 경로상 다음 정지선에 가라/서라 |
| `/perception/obstacle_segmentation/pointcloud` | **빈 더미** | (perception) | |
| `/perception/occupancy_grid_map/map` | **전부 free 더미** | (perception) | |
| `/tf` (map→base_link) | ego GT pose | (localization) | |
| `/vtd/raw_rx`·`/vtd/raw_tx`·`/vtd/respawn` | 원본패킷·리스폰 | 자체 | bag 기록용 |

## 3. Planning 체인 — 정확한 토픽 (★ 최종 궤적 = `/planning/trajectory`)

```
[vtd_route_node] ──/api/routing/set_route(_points)──► [mission_planner] (+route_selector)
        │
        └─► /planning/mission_planning/route ─────────────────────────────┐
                                                                          ▼
[scenario_selector]  (current_scenario = LaneDriving)  ◄─ route, kinematic_state, operation_mode
   ▲ 입력 /planning/scenario_planning/lane_driving/trajectory
   │        ▲
   │   [lane_driving]  behavior_path_planner ─► behavior_velocity_planner
   │        ─► motion_planning( elastic_band_smoother ─► path_optimizer(acados MPC) ─► motion_velocity_planner )
   │        ─► /planning/scenario_planning/lane_driving/trajectory   (10Hz)
   │
   └─► /planning/scenario_planning/scenario_selector/trajectory   (10Hz)
                    │
                    ▼
        [velocity_smoother]  ─► /planning/scenario_planning/velocity_smoother/trajectory   (10Hz)
                    │
                    ▼
        [planning_validator]  ─► ★★ /planning/trajectory ★★   (10Hz, 진짜 최종)
                                   (+ /planning/planning_validator/validation_status)
```

- **parking 시나리오도 실행 중**(freespace_planner·costmap_generator) — 단 current_scenario=LaneDriving 이라 대기.
- planning_validator param: `default_handling_type: 0`. validation_status 로 각 검사 결과 발행.
- ⚠ **`/planning/scenario_planning/trajectory` 는 미사용**(발행자 0). 최종은 `/planning/trajectory`.

## 4. Control 체인 (이미지의 복잡한 제어 출력부)

```
/planning/trajectory
   │
   ▼
[trajectory_follower/controller_node_exe] (lateral+longitudinal)
   ├─► /control/trajectory_follower/control_cmd ───────────────┐
   │                                                           │
[autoware_shift_decider] ─► /control/shift_decider/gear_cmd ───┤
[external_cmd_selector/converter] ─► /external/selected/* ─────┤
[MRM/emergency] ─► /system/emergency/* ───────────────────────┤
/system/operation_mode/state, /autoware/engage ───────────────┤
                                                               ▼
                                              [vehicle_cmd_gate]  (안전필터·중재·모드게이팅)
                                                               │
              /control/command/control_cmd (+gear_cmd, turn_indicators_cmd, hazard_lights_cmd)
                                                               ▼
                              [vtd_autoware_bridge] ─► CtrlPacket(steer,accel,turn) ─► VTD
```

- 표준 경로의 gate → **raw_vehicle_cmd_converter → vehicle_interface → CAN → 실차** 를 우리는 **브리지가 gate 출력을 직접 받아** 대체(끔).
- 병렬 검증: `control_validator`(control_validator/validation_status), AEB(IMU 또는 예측궤적 필요 — IMU 공급으로 해소), lane_departure_checker.
- 모드: `operation_mode_transition_manager` + 시스템 `command_mode_decider`. 진단그래프 `/autoware/modes/autonomous` 가 OK여야 autonomous 유지.

## 6. 핵심 교훈 (혼동 방지)
1. **최종 궤적 = `/planning/trajectory`** (planning_validator 발행). `scenario_planning/trajectory` 아님.
2. 궤적 체인 마디: lane_driving/traj → scenario_selector/traj → velocity_smoother/traj → **/planning/trajectory**. 어디서 끊기는지 볼 땐 이 4개를 순서대로 확인.
3. autonomous 유지 3요소: 진단그래프 OK(브리지가 initialization_state·objects·control_mode 등 소스충족) + /planning/trajectory 흐름 + IMU(AEB).
4. 제어 출력은 gate가 shift_decider gear_cmd·MRM·operation_mode 를 중재 → 브리지가 gate 출력만 받으면 됨.
