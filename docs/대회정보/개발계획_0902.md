## 0. 현재 상태 한 줄 요약

- **Autoware 실기 모드는 차가 움직이지 않는다.** 브리지 토픽명 오류, system 미기동으로 인한 명령 게이트·engage 차단, 점군·점유격자 부재로 궤적 미발행, 측위 초기화 상태 부재. 각각 단독으로 치명. psim E2E는 이 결함들을 검증하지 못한 구성이었음.
- **신호등은 브리지·맵·Autoware 판정 규칙 세 층이 전부 어긋남.** TlRouter는 실제 맵에서 100% 예외(발행 0건), 맵 신호등 절반이 반대 차로, lanelet당 3~10개 중복, state 4·6은 Autoware 규칙상 영구 정지. `is_simulation:=true`가 이 실패를 "통과"로 감춤.
- **자체 스택은 인자 없이 실행하면 대회장 VTD를 정지·재로드.** 곡률 NaN으로 곡선 중간 조향 0 + 급제동. 15항목 중 구현 1개.
- **건전한 것**: xodr 파서 기하(spiral 2mm), 차선 그래프 연결성, 9910 바이트 프로토콜, 조향 부호, 좌표계.
- **미사용 자원**: xodr에 정지선 object 710개, 횡단보도 object 197곳, 노면 화살표, signal validity, controller 묶음 214개, elevationProfile이 전부 있음. 붉은 노면만 xodr에 없고 osgb 텍스처(`StyleSrfBikeway.rgb`)에 있음, 후보 x 478~522 / y −142~−68. xodr에 geoReference 없음(로컬 좌표) → 외부 지도 사용 불가.

## 1. 근본 원인 5가지와 원인 수준의 해결

| # | 원인 | 파생 문제 | 원인 수준 해결 |
|---|---|---|---|
| R1 | **검증 대상 ≠ 실제 구성.** psim은 브리지·실기 launch 인자를 쓰지 않음 | 토픽명, system, 점군, 초기화 상태 | **회귀 기준을 "실기 launch + 브리지 + mock VTD"로 교체.** mock_vtd.py에 신호등·리스폰·끊김 시나리오 추가. 이 회귀 통과가 커밋 조건 |
| R2 | **브리지가 Autoware 입력 계약을 소스 대조 없이 작성** | 토픽명, 필수 구독, 가용성, 초기화 | **계약 대조 도구**: 실기 모드 기동 후 `ros2 node info`로 "구독자만 있고 발행자 없는 토픽" 목록 생성. 브리지 발행 이름은 이 목록과 diff로 검증 (remap 아님, 브리지가 정확한 이름으로 직접 발행) |
| R3 | **맵 변환기가 기하만 검증, 의미 정보는 근사·생략** | 신호등 방향·중복, turn_direction, 횡단보도 0, speed 일괄 50, z=0 | **의미 계층을 xodr 원 데이터로 재작성** + **의미 검증기**(lanelet2 python으로 로드해 Autoware 판정 규칙 기준 전수 검사) |
| R4 | **신호등 채널이 VTD 정보 형태(방향 판정 완료된 상태 1개)와 Autoware 형태(규제요소별 색·모양)의 차이를 흡수 못 함** | TlRouter 버그, 첫 그룹만 발행, state 4·6, 리스폰 고착 | **브리지가 가라/서라를 결정하고 Autoware엔 녹색 원형/적색 원형만 전달.** 대상은 "경로상 다음 정지선의 규제요소 전부". 현재 lanelet은 매 프레임 폴리곤 포함 판정(전역) → 리스폰 고착 원리적 제거 |
| R5 | **연구실 자동화와 대회장 도구가 한 파일** | run_real 기본값이 SCP 재시작 | **대회장 러너에서 SCP 코드 경로 제거.** scp_ctrl·카메라는 연구실 전용 디렉토리로 분리 |

공통: 문서에 사실을 적을 때 **확인한 명령·스크립트를 함께 적는다** ("횡단보도 2개뿐", "engage 미검증", "psim E2E 통과" 같은 미검증 기록 재발 방지).

## 2. 방향 결정

**Autoware 주 스택 유지. 브리지를 "Autoware 입력 계약에서 출발해 재설계한 어댑터 패키지"로 재구성. 맵 의미 계층 재작성. 자체 스택은 완주 전용 폴백으로 축소.**

근거: 발견된 결함 중 Autoware 자체 결함은 0. 전부 브리지·맵·launch 구성이고 수정 규모는 각 수 줄~수십 줄. 자체 스택으로 15항목을 열흘 안에 구현하는 것보다 통합 결함 수정이 훨씬 싸고 확실. 단, **R1·R2를 먼저 해결한 뒤** 브리지를 고친다(순서 어기면 저녁 연동에서 같은 종류 결함 재발).

맵 데이터 우선순위: **xodr 원 데이터 → 같은 패키지의 osgb(붉은 노면만) → 규정 디폴트(50/30km/h)**. 외부 지도 불가(채점 세계는 시뮬 내부, xodr에 지리참조 없음).
