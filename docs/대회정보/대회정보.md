## 6. 통신 인터페이스

모든 바이너리 필드 **little-endian, 헤더/패딩 없음**. 근거: 인터페이스 API.xlsx + libHLVTD.so `sendDataPacket` 디스어셈블 + 시뮬 PC `~/HLFMA/docs/07-sensor-interface.md`.

| 채널 | 프로토콜 | 포트 | 방향 | 내용 |
|---|---|---|---|---|
| 상태/제어 | TCP | 9910 | 양방향 (단일 연결) | 차량 상태 수신(1109B @20Hz) + 제어 송신(9B) |
| LiDAR | UDP | 9912 | VTD → 제어기 push | 포인트클라우드 (42B 헤더 + xyz) |

### TCP 9910 수신 — DataPacket (1109 bytes 고정, 20Hz)

| offset | 크기 | 필드 | 형식 |
|---|---|---|---|
| 0 | 24 | egoX, egoY, egoZ, egoHeading, egoPitch, egoRoll | 6 × float32 (m, rad) |
| 24 | 1080 | objects[30] — 슬롯당 36B | `id(u32), x, y, z, heading, speed, length, width, height(8×f32)` |
| 1104 | 4 | trafficLightId | int32 |
| 1108 | 1 | trafficLightState | uint8 |

- objects: 항상 30슬롯 고정, `id == 0` 무효(전부 0). Ego 제외, 월드좌표(m), 수평거리 **80 m 이내**를 가까운 순 정렬, 초과분 잘림
- 신호등: **경로 기준으로 선택된 1개만** 전송. state: 0=미할당 / 1=적 / 2=황 / 3=녹 / 4=좌회전 / 5=녹+좌 / 6=점멸
- **(9/1 공식 Q&A) trafficLightId는 개별 신호등 위치/순서와 매핑되지 않음** — 교차로에는 직진·좌회전용 복수의 신호 제어기가 있고, GT는 그중 **Ego 진행방향에 내부적으로 매핑된 제어기의 상태를 대표값으로** 줌. **ID는 무시하고 state만 기준으로 주행할 것.** 신호등 위치·정지선은 xodr에서 자체 추출 (→ 브리지의 xodr_signal_id 매핑 방식은 폐기, "경로상 다음 신호등에 state 적용" 방식으로 변경 필요)
- **(9/2 AIM팀 답변) 교차로 진입 시 신호 정보(state) 0으로 끊김** — 신호등 정보는 교차로 진입 전 '접근로'를 기준으로만 제공되며, 교차로 내부 진입 시 0으로 갱신됨. 따라서 **교차로 진입 전에 수신한 신호(state)를 기억하여 통과/정지 여부를 유지**하는 로직 필수.
- **(9/2 공식 답변, #4939) state 6은 적·황 점멸을 구분하지 않음** — "제공되는 센서를 활용해 판단" (= 카메라로 색 식별하라는 뜻). 카메라 미사용 시 보수적 처리: **state 6이면 무조건 정지선에서 일시정지(0.5초) 후 통과** (황색점멸에서 일시정지해도 감점 항목 없음. 항목 8 "녹색신호 무정차"는 녹색에만 적용)
- **(9/2 공식 답변) objects[].id는 동일 객체가 시나리오에 존재하는 동안 유지됨**. 객체 삭제·재생성 후에는 ID가 바뀌거나 재사용될 수 있음 → id 기반 추적 가능, 단 id 재사용 대비 위치 점프 검사 병행
- **(9/2 공식 답변) ego 속도는 GT API에 없음 — 평가 시스템은 VTD 내부 RDB의 실제 속도로 판정**. 우리 추정치(pose 차분, 20Hz)와 어긋날 수 있으므로 **속도 마진을 더 둘 것**(목표속도 = 제한 –2~3km/h). 참고: RDB raw(48190)에서 실제 속도를 읽어 추정치와 대조 검증 가능
- TCP 스트림이므로 정확히 1109B 단위 재조립 후 파싱

```python
import struct
FMT = '<6f' + 'I8f'*30 + 'iB'   # calcsize = 1109
def parse(buf):
    v = struct.unpack(FMT, buf)
    ego = v[0:6]
    objs = [v[6+9*i : 6+9*(i+1)] for i in range(30) if v[6+9*i] != 0]
    tl_id, tl_state = v[-2], v[-1]
    return ego, objs, tl_id, tl_state
```

### TCP 9910 송신 — CtrlPacket (9 bytes)

`struct '<ffB'` = **steering(f32, rad) + targetAccel(f32, m/s²) + turnSignal(u8: 0=끔/1=좌/2=우)**

- 예제 기준 20Hz 전송, 조향 ±0.35 rad (차량 한계는 0.48 rad), 가속 +3.0 / -6.0 m/s²
- **(9/1 실측 확정) 조향 부호: +steer = 좌회전(CCW), −steer = 우회전(CW)** — 수학 표준·Autoware 규약(좌+)과 동일. 예제 코드의 `-steer` 반전은 키매핑(D키=+) 문제였을 뿐. 자체 스택 mock(자전거 모델)도 같은 규약이라 수정 불필요. 실측: steer=+0.2 → Δheading +0.478rad(좌), steer=−0.2 → −0.923rad(우)
- NaN/Inf 패킷은 플러그인이 무시 (`non-finite CONTROL packet ignored`)
- 연결 끊기면 시뮬 쪽에서 steering=0, accel=0 처리
- **방향지시등은 평가 항목**: 차로 변경 시 **3초 내** 미점등이면 경미 감점 (안내문 항목 13)

### UDP 9912 — LiDAR

패킷 = 42B 헤더 + N × 12B 포인트(float32 x,y,z), 기본 512pts/pkt, 34,752pts/frame

헤더 `'<IHIQdHHIIHBB'`: `magic('IVHL'=0x4C485649), version(=1), frame_id, timestamp_ns, sim_time_sec, packet_index, packet_count, point_count_total, point_start_index, point_count_in_pkt, coordinate_mode(1=world), point_stride_bytes(=12)`

- **월드 좌표계** 전송 → base_link 기준 필요 시 ego pose로 역변환 (시뮬 PC `docs/08-ros2-sensor-bridge.md`)
- (0,0,0) 포인트 무효 → 필터링

### RTSP 8554 — 카메라

```bash
ffplay -rtsp_transport tcp -fflags nobuffer -flags low_delay rtsp://<VTD_PC_IP>:8554/front
```
- **TCP 인터리브드 전용** (`-rtsp_transport tcp` 필수, UDP 비활성)

### 검증 방법

VTD 기동 로그에서 `TCP 9910 unified: DataPacket 1109B / CtrlPacket 9B` 확인, 또는 9910 접속 후 수신 바이트가 1109의 배수인지 확인.

## 7. 대회 당일 진행·평가·채점 — 대회 안내문 PDF(8/27)로 확정

### 7A. 당일 진행 방식

**당일 일정**: 09:00 개회식 → 09:30~10:00 대회 준비·**평가 순번 공지** → 10:00~12:00 오전 평가 → 12:00~13:00 중식(**미제공**) → 13:00~18:00 오후 평가 (연장 가능)

- **제어기 PC 제출**: 당일 아침 모든 팀이 제어기 PC를 **전원 OFF 상태로 제출**
- **두 팀씩** 나와 평가, 팀당 **20분** — 이 안에 **시스템 연동부터 평가까지 전부** 완료해야 함. 20분 종료 시 즉시 평가 종료(초과 불가) → **부팅~연동 소요시간 리허설 필수**
- **재평가**: 20분 내 시간이 남으면 1회 더 시도 가능. 단 **첫 시도에서 완주했으면 첫 완주 기록으로 산정**. 완주 못 한 채 시간 종료 → 미완주
- **완주(종료) 판정**: 제어 차량 **뒷바퀴 축**(= ego 좌표 원점)이 종료 지점을 통과하면 종료. 콘(Cone)은 대략적 위치 표시용이고, 실제 판정은 **운영측 제공 종료 지점 좌표** 기준 (콘은 그 좌표에서 도로 t방향(횡)으로 배치)
- **결과 발표**: 당일 순위 비공개(개인별 점수는 공개). 종료 후 별도 집계, 팀별 결과 보고서 출력·희망 팀은 이메일 송부

### 7B. 채점 방식

- 경로를 **여러 구간으로 나눠 구간별 독립 평가**, 각 구간 **100점에서 시작**
- **경미 위반 –3점 / 중대 위반 –6점** (경미 상태에서 심화되면 +3 추가돼 총 –6)
- 한 구간 내 **동일 항목은 1회만 감점**
- **리스폰**: 구간별 1회 허용, 초과분부터 1회당 –6점 누적
- **총점** = 구간 점수 합. 구간 점수는 마이너스까지 내려갈 수 있고 그대로 합산됨 (예: 80 + 80 + (–150) = 10점)
- **미완주 시**: 실제 도달한 구간까지만 만점으로 집계 (3구간 중 2구간 종료 → 200점 만점 기준)

### 7D. 순위 산정

**완주 그룹이 미완주 그룹보다 항상 우선** (완주팀 전원 > 미완주팀 전원).

- 완주 그룹: ① 총점 → ② 완주 시간(빠른 팀) → ③ 중대 위반 횟수(적은 팀)
- 미완주 그룹: ① 주행 거리(먼 팀) → ② 총점 → ③ 중대 위반 횟수
- 전략 시사점: **완주가 최우선 목표**. 완주 그룹 내 동점 시 완주 시간이 갈라 속도도 중요하지만, 감점(–3/–6) 대비 이득이 크지 않으므로 법규 준수 우선

(참고 — 설명회 당시 항목 분류: 법규 10개 S-코드 + 동적 이벤트. 위 15개 확정 기준이 우선함)
