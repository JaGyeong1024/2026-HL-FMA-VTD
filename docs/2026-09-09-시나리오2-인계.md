## 5. 해결된 것 (증거 포함)

### 5.1 `isNeverAvoidanceTarget` 무조건 게이트 — `utils.cpp:813`

내 차로에 있고 옆 차로가 `road_shoulder` 가 아니면 **무조건** 회피 제외.
파라미터가 없어 끌 수 없고, Autoware 자신의 `avoidance_for_ambiguous_vehicle` 정책에
도달조차 못 한다. 맵에 `road_shoulder` 를 넣어도 다음 줄 `is_disjoint_right_lane` 에서
또 걸린다 (객체가 그 갓길 차로를 실제로 물고 있어야 함 — 차로 정중앙이라 불가).

→ 정지 시간/이동 거리 조건을 만족하면 ambiguous 정책으로 판단을 넘긴다.
`policy_ambiguous_vehicle: "ignore"` 로 되돌리면 기존 거동과 완전히 동일.

**부작용**: `object.stop_time` 이 1.2~2.8 s 부근에서 동결되는 현상 때문에
`th_stopped_time` 을 3.0 → 0.5 로 낮춰야 했다. **동결 원인 미규명.**

### 5.2 회피 방향을 공간 기준으로 — `scene.cpp` `createObjectData`

업스트림은 편차 **부호만으로** 방향을 정한다. route preferred 가 좌회전 차로라
참조 경로가 lane3 을 따라가고, 자차로의 차단 차량이 경로 기준 2.3~6.4 m 떨어져 보인다.
그 결과 여유 0.5 m 인 좌측으로 회피하려다 `INSUFFICIENT_DRIVABLE_SPACE`.

→ 부호로 정해진 쪽 여유가 `getAvoidMargin()` 최소 요구치에 못 미치고
반대쪽은 충족하면 뒤집는다. 요구치는 기존 파라미터로만 계산:
`lateral_hard_margin + 0.5W + hard_drivable_bound_margin + 0.5W = 2.386 m`

### 5.3 모듈 굶주림 (가장 큰 건) — `planner_manager.cpp:517`

```cpp
exclusive_module_exist_in_approved_pool =
    any_of(approved_module_ptrs_, [](m){ return !isSimultaneousExecutableAsApprovedModule(m); });
if (is_this_not_joinable) continue;   // isExecutionRequested 조차 호출 안 됨
```

승인 풀에 배타 모듈(`as_approved:false`)이 **하나라도** 있으면 다른 전 모듈이
평가에서 통째로 빠진다. `blocked_route_detour` 가 외부 차선변경을 상시 요청하는데
그 모듈이 배타라, 승인되는 순간 `static_obstacle_avoidance` 가 영구 굶주림.

**계측**: `createObjectData` 호출이 **67회에서 멈춤 → 수정 후 3079회.**

```yaml
external_request_lane_change_left/right, avoidance_by_lane_change
    enable_simultaneous_execution_as_approved_module: false -> true
static_obstacle_avoidance
    enable_simultaneous_execution_as_candidate_module: false -> true
```

이것 때문에 회피 마커가 얼어붙어 보였고, 내가 그 stale 값을 현재 상태로 오독했다.

### 5.4 `planning_validator` 가 회피를 죽임

정상 회피 기동의 횡 이동이 `trajectory_shift.lat_shift_th 0.5 m` 를 넘어
소프트스톱 궤적으로 대체 → ERROR 진단 → **MRM 비상정지**.

```yaml

trajectory_shift.override_error_diag: false -> true
```

## 6. 남은 문제 — 좌회전 차로 진입

자차는 `14925`(lane4)에 있고 좌회전은 `14855→14611`(lane2). **2개 차로.**

### 6.1 Autoware 는 한 번에 2차로를 못 옮긴다

```cpp
// utils.cpp:397  get_target_lane_for_non_mandatory_lane_change
const auto left_lanes = routing_graph_ptr->left(ref_lane);   // 인접 1개만
```
로그의 실제 shift 값도 `3.20 m` (차로 폭 1개분). 2차로는 **순차 2회**만 가능.

### 6.2 옆으로 미는 방법은 좌회전 진입에 쓸 수 없다

```cpp
// utils.cpp:1744  getCurrentLanesFromPath
const auto idx = planner_data->findEgoIndex(path.points);
const auto start_id = path.points.at(idx).lane_ids.front();   // 경로가 들고 있는 lane_id
```

차로열은 **자차의 실제 위치가 아니라 경로의 `lane_ids`** 에서 나온다.
→ 자차를 물리적으로 `14855` 안에 밀어 넣어도 lane_id 는 안 바뀌고 계속 직진 경로를 낸다.
→ **회피 shift / side_shift / path_sampler 는 전부 좌회전 진입 수단이 될 수 없다.**
   (봉쇄 통과에는 유효하다.)

### 6.3 관측된 거부 사유

```
Skip: prepare length out of expected range.  length: 0.00000, threshold min: -27.47777, max: -7.67565
```

**`max` 가 음수다.** `max_length_threshold = dist_to_terminal_start` 이고

```
dist_to_terminal_start = dist_to_terminal_end - dist_buffer
dist_buffer            = 남은 차선변경 횟수만큼의 최소 길이 합
```

음수라는 건 **차선변경을 시작했어야 할 지점을 이미 지났다**는 뜻이다.

1회당 소요:
```
전이 + prepare + backward_length_buffer_for_end_of_lane(3.0) + lane_change_finish_judge_buffer(2.0)
```

### 6.4 창(window) 계산 — 여유가 사실상 0

```
창 시작 : 좌1 대기열 꼬리 통과 지점 (rel +19.2, 약 (297,-23))
창 끝   : 33m행 끝 = 차선변경 마감점 (약 (312,-45))
창 길이 : 약 26.6 m
2회 buffer : 약 26.6 m
→ 여유 ≈ 0
```

**이게 문제의 본질이다.** 좌1 대기열이 좌회전 차로 진입 마감점 직전까지 이어져 있어서,
우회로 통과 후 좌측 복귀에 쓸 거리가 남지 않는다.

### 6.5 왜 대기열 전에 미리 좌측으로 못 갔나

```
RTC={lane_change_left: [(False, 19.0, 74.3, 0)]}
                          ↑ False = 안전하지 않음
```

13 m/s 접근 시 차선변경 1회가 **prepare 19 m + 전이 55 m = 74 m** 를 차지한다.
그 끝점이 대기열 안에 떨어져 unsafe 판정. (추정: 저속이면 span 이 줄어 대기열 전에 들어감)

또한 좌1 로 미리 옮겨도 소용없다 — 좌1 은 rel +1.9 부터 막혀서
자차로(+8.6)보다 **더 일찍** 막힌다.

## 7. 내가 틀렸던 것 (반복 방지)

1. **"obstacle_stop 0.2 로 뚫었다"를 패치 효과로 단정** — 같은 코드로 3회 중 1회만 성공.
   n=1 을 커밋 메시지에 "검증"이라 적었다.
2. **빨간불 `not_use_adjacent_lane` 이 원인** — 아님. 신호 색이 바뀌어도
   `to_drivable_bound` 는 0.83/1.04 로 미동도 없었다.
3. **`calcDistanceToAvoidStartLine` 이 회피 시작을 늦춘다** — 반대다.
   신호등이 장애물보다 멀면 `nearest_avoid_distance`(= 가장 이른 시작)를 반환한다.
4. **회피 디버그 마커가 fresh 하다** — stale 이었다. 모듈이 평가되지 않는 동안에도
   매니저가 이전 마커를 계속 발행한다. `stop_time` 이 동결돼 보인 것도 이 때문.
5. **물리적으로 옮기면 lane_id 가 따라온다** — 아님 (6.2 참조).
6. **"우측 차선변경이 원래 됐었다"** — 3회 주행 342회 시도 전부 `candidate_paths=0`.
   `detour2_early` 의 route preferred 재작성이 매번 거부됐다:
   `change_route: False "Cannot reroute as the planner is not in lane following."`
   (`reroute_availability == false`. 스크립트가 `fired=True` 로 1회만 시도하고 포기)
7. **`ng_av.sh` 로 `[6]`단계를 갈아끼우면서 `detour2_early` 를 빼놓고** 그 결과를
   시스템 기본 동작으로 오독했다. 구성요소를 뺐으면 그걸 먼저 의심해야 한다.
